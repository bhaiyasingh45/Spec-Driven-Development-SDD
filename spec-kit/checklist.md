# SDD Review Checklist

Use this checklist before considering a spec-driven change complete.

## Specification

- [ ] Problem and desired outcome are clear.
- [ ] Scope and non-goals are documented.
- [ ] User scenarios are concrete.
- [ ] Requirements are testable.
- [ ] Acceptance criteria are explicit.

## Planning

- [ ] Architecture impact is understood.
- [ ] Dependencies are identified.
- [ ] Risks and trade-offs are documented.
- [ ] Tasks are small and independently verifiable.

## Implementation

- [ ] Implementation follows the approved plan.
- [ ] Automated tests cover acceptance criteria.
- [ ] Documentation is updated where behavior changed.
- [ ] Any requirement changes are reflected in the spec.

## Final Review

- [ ] All acceptance criteria pass.
- [ ] No unresolved assumptions remain.
- [ ] The spec and implementation describe the same behavior.
