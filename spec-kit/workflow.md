# Spec Kit Workflow

## 1. Constitution

Define the principles that every change must follow: architecture, code quality, testing, security, and documentation standards.

## 2. Specify

Describe the desired behavior in plain language. Focus on the problem, user scenarios, requirements, and acceptance criteria rather than implementation details.

## 3. Plan

Translate the specification into an implementation approach. Identify components, interfaces, data flow, dependencies, and technical trade-offs.

## 4. Tasks

Break the plan into small, independently verifiable tasks. Each task should have a clear outcome and reference the relevant requirement.

## 5. Implement

Implement the tasks against the approved specification. Validate the result against the acceptance criteria and update the specification when requirements change.

## Guiding Principle

The specification is the source of truth. Code is an implementation of the specification, not a replacement for it.
